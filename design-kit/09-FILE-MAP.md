# 09 · FILE MAP (original project → what to keep)

The original project (`ChitChat-App-clean-fixed-2026-10-20/source_code/`) is a Go module
named `chitchatbot`. This is the map an agent needs to navigate it, with a verdict per area.

Legend: **KEEP** = reuse as-is · **ADAPT** = same pattern, new content · **DROP** = domain
logic, do not port · **REF** = only in `reference/` of this kit for study.

## 1. Top level

| Path | What it is | Verdict |
|---|---|---|
| `wails.json` | Wails config: name, `outputfilename`, frontend dir, asset dir | **KEEP** (change name/output) |
| `go.mod`, `go.sum` | Go 1.24, Wails v2.12.0, Badger v4.9.1, rod, chromedp, utls | **KEEP** deps you use |
| `main.go` | `go:embed` dist, `resolveDataDir()`, `wails.Run(...)`, window size/colour, WebView2 profile | **KEEP** |

| `install.bat`, `run-dashboard.bat`, `test.bat`, `verify.bat`, `apichat.bat` | Installer/builder/runner for Windows | **ADAPT** |
| `package.json` | Dev-only verification tooling (`node --test`, jsdom, fflate) | **KEEP** |

## 5. Suggested layout for a derived app

```
myapp/
├── wails.json                 name + outputfilename
├── main.go                    embed + wails.Run (+ data dir + webview dir)
├── app.go                     App struct: 8–12 methods, mutex, emit, log
├── internal/
│   ├── model/                 settings structs, Default*(), Snapshot
│   ├── uistore/               Badger: settings/* + logs/*
│   ├── applog/                file logger (redacting)
│   └── <domain>/              YOUR logic (workers, API client, scraper…)
├── cmd/<name>/ui/             index.html · styles.css · app.js   ← from starter/
├── tests/                     contract + ui tests (node --test + jsdom)
├── scripts/                   verify, package, bundle
├── data/                      runtime (gitignored)
└── build/                     generated (gitignored)
```

`.gitignore` the same things the original did: `build/`, `dist/`, `data/`, `*.exe`,
`verification-output/`.
